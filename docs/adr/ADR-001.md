# ADR-001: Handling Async Context and Stream Lifecycle in NotesScreen and AuthRepository

**Date:** 2026-11-11  **Author:** Sukru Can Ozturk  **Milestone:** Lab 5
**Tool and model used:** Antigravity (Gemini)

## Context
In Lab 5, we needed to implement `AuthRepository` to map `FirebaseAuthException` codes into user-friendly `AuthFailure` messages, and `NotesScreen` to display a live Firestore stream of user notes while supporting adding notes via `AddNoteDialog` and deleting notes via `Dismissible`. A common pitfall in Flutter is calling `watchNotes(uid)` directly inside `build()` (which recreates the Firestore stream on every widget rebuild) or calling `context.read()` / `ScaffoldMessenger.of(context)` after an `await` gap when `showDialog` finishes.

## Prompt
```
Implement NotesScreen with an AppBar ('My Notes' and Sign out button), a FloatingActionButton ('Add note') that opens AddNoteDialog and calls NotesRepository.addNote (showing a SnackBar 'A title is required.' on ArgumentError), and a StreamBuilder over _notes that handles error, waiting, empty state, and a ListView of Dismissible ListTiles. Also implement AuthRepository.messageFor using a Dart 3 switch expression.
```

## Result
We stored `_notes` as a `late final Stream<List<Note>>` field in `_NotesScreenState` so the Firestore snapshot listener is created only once per state lifecycle, and captured `NotesRepository` and `ScaffoldMessengerState` before awaiting `showDialog`:

```dart
  Future<void> _add() async {
    final notesRepo = context.read<NotesRepository>();
    final messenger = ScaffoldMessenger.of(context);
    final result = await showDialog<(String, String)>(
      context: context,
      builder: (_) => const AddNoteDialog(),
    );
    if (result == null) return;
    try {
      await notesRepo.addNote(widget.uid, result.$1, result.$2);
    } on ArgumentError {
      messenger.showSnackBar(
        const SnackBar(content: Text('A title is required.')),
      );
    }
  }
```

And in `AuthRepository.messageFor`:
```dart
  static String messageFor(String code) {
    return switch (code) {
      'invalid-email' => 'The email address is not valid.',
      'weak-password' => 'The password must be at least 6 characters.',
      'email-already-in-use' => 'An account already exists for this email.',
      'invalid-credential' || 'wrong-password' || 'user-not-found' =>
        'Wrong email or password.',
      'network-request-failed' => 'No connection. Check your network.',
      _ => 'Sign-in failed. Please try again.',
    };
  }
```

## Rejected suggestion(s) — at least one
1. **Calling `context.read<NotesRepository>().watchNotes(widget.uid)` directly inside `build()`:** Rejected because every rebuild of `NotesScreen` would subscribe to a new Firestore snapshot stream, causing unnecessary reads and UI flickering.
2. **Using `ScaffoldMessenger.of(context)` after `await showDialog(...)` and `await notesRepo.addNote(...)`:** Rejected because `use_build_context_synchronously` lint warns against using `BuildContext` across async gaps if the widget could be unmounted while awaiting. Capturing `notesRepo` and `messenger` before the first `await` avoids any stale context issue.
3. **Storing `id` inside `Note.toFirestore()`:** Rejected because in Firestore the document ID is part of the document path (`users/{uid}/notes/{noteId}`), not a duplicated field inside the document payload, and `lab05_test.dart` explicitly verifies `expect(map.containsKey('id'), isFalse)`.

## Verification
